# 01 Setup

This page takes you from a fresh laptop to a running copy of Tap Review. It is updated at each milestone; sections for sign-in, deployment and seeding are added as those parts are built.

## Accounts you need

1. **GitHub**: repository `Gaurang58/tapnreview`.
2. **Supabase**: one project in the London region. Keep its URL, publishable key and secret key.
3. **Vercel**: a new project made from the GitHub repository (milestone 8).

## Install

| Command | What it does |
| --- | --- |
| `nvm use` | Switches to Node 22, the version this project is built on |
| `npm install` | Downloads the libraries listed in `package.json` |
| `cp .env.example .env.local` | Makes your private settings file (never committed) |

## Environment variables

Set these in `.env.local` locally and in Vercel (Settings, Environment Variables) when deployed.

| Variable | What it is |
| --- | --- |
| `PUBLIC_APP_URL` | The address of the app, no trailing slash. It is written into QR codes and NFC tags, so changing domain later is a single edit here |
| `NEXT_PUBLIC_SUPABASE_URL` | Your Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Safe-to-share key used by the browser; Row Level Security still protects the data |
| `SUPABASE_SECRET_KEY` | Powerful key that bypasses access rules. Server only. Never put it in the browser or commit it |
| `SUPABASE_PROJECT_REF` | The part of the project URL before `.supabase.co` |
| `VISITOR_HASH_SALT` | A long random string mixed into the anonymous visitor fingerprint |
| `DEMO_*_EMAIL` / `DEMO_*_PASSWORD` | The four demo logins created by the seed script (milestone 7) |
| `REAL_STORE_PLACE_ID` | Google Place ID for the physical card's store |

## Database

The database is described by the five SQL files in `supabase/migrations/`, applied in order with `supabase db push` after `supabase login` and `supabase link --project-ref <ref>` (see the build log for a note on migration history on the current project, where they are already applied). To check the rules without touching Supabase at all, run `npm run test:db`.

## Run locally

`npm run dev` starts the app at http://localhost:3000.

## Supabase Auth settings (one-off, in the Supabase dashboard)

Authentication, then Sign In / Providers:

1. Switch **off** "Allow new users to sign up". Accounts are created only by the invite action. (The invite action still works with sign-ups off.)
2. Set the minimum password length to 10 or more.

No email templates or redirect URLs are needed: invitation links are generated by the app and shown to the inviter to pass on.

## Demo data

| Command | What it does |
| --- | --- |
| `npm run seed:demo` | Creates the organisation, 3 areas, 10 cities, 12 stores, 15 tags, 4 demo logins and about 18,000 demo taps over 180 days (all marked demo; 180 so the 90-day view has a previous 90 days to compare with). Safe to run again. Prints your physical card's `/t/` and `/q/` addresses |
| `npm run seed:reset` | Removes every demo tap. Real taps, tags, stores and logins stay |

Needs `SUPABASE_SECRET_KEY` and the `DEMO_*` values in `.env.local`. Only the Nottingham West Bridgford store has a real Google Place ID (from `REAL_STORE_PLACE_ID`); the other stores use obvious placeholders, so their review links are not real.

## First admin

The first Admin is created by the demo seed. For a real pilot, create the user in the Supabase dashboard (Authentication, Users, Add user) and add one `memberships` row with role `admin` and the organisation id, using the SQL editor.
